# 1.7-Version Enhancements WRT Exception Handling
As a part of 1.7-version in exception handling the following two concept introduces-
1. try with resources
2. multi-catch block
## 1. try with resources
until 1.6-version it is highly recommended to write `finally` block to close resources which are opened as a part of `try` block.
```java
BufferedReader br = null;
try {
	br = new BufferedReader(new FileReader("input.txt"));
	// use br based on our requirement
} catch (IOException e) {
	// handle code
}
```
the problem in this approach are:
- Compuslory programmer is required to close resources inside `finally` block. it increases complexity of programming.
- we have to write `finally` block compulsory and hence it increases length of the code and reduces readability.
- To overcome above problems **Sun** peoples introduced **try with resources** in 1.7-version. The main advantage of try with resources is whatever resources we open at the part of `try` block will be closed automatically. 
	Once control reaches end of `try` block either normally or abnormally and hence we are not required to close explicitly so that complexity of programming will be reduced.
- We are not required to write `finally` block so that length of the code will be reduced and readability will be improved.
```java
try (BufferedReader br = new BufferedReader(new FileReader("input.txt"));) {
	// use br based on our requirement
	
	/* br will be closed automatically once control reaches end of try block 
	* either normally or abnormally and we are not responsible to close
	* explicitly
	*/
} catch (IOException e) {
	// handle code
}
```
### Conclusion
1. We can declare multiple resources but those resources should be separated with semicolon.
	**Syntax:**
	```java
	try (R1; R2; R3) {

	}
	```
	**Example:**
	```java
	try (
		FileWriter fw = new FileWriter("output.txt"); // resource-1
		FileReader fr = new FileReader("input.txt"); // resource-2
	) {
	
	}
	```
2. 
	- All resource should be `AutoCloseable` resources.
	- A resource is said to be autoclosable if and if corresponding class implements **`java.lang.AutoCloseable`** interface.
	- All IO-related resource, DB-related resource & Network-related resources are already implemented `AutoCloseable` interface.
	- Being a programmer we are not required to do anything just we should aware the point.
	- `AutoCloseable` interface came in 1.7-version and it contains only one method `close()` → `public void close()`.
3.  All resource reference variable implicitly `final` and hence within `try` block we can't perform reassignment otherwise we will get compile-time error.
	```java
	import java.io.BufferedReader;
	import java.io.FileNotFoundException;
	import java.io.FileReader;
	import java.io.IOException;
	
	public class Test {
	
		public static void main(String[] args) throws FileNotFoundException, IOException {
			
			try (BufferedReader br = new BufferedReader(new FileReader("input.txt"))) {
				
				// Error: The resource br of a try-with-resources statement cannot be assigned
				br = new BufferedReader(new FileReader("output.txt")); 
			}
		}
	
	}
	```
	
	
4. Until 1.6-version `try` should be associated with either `catch` or `finally` but from 1.7-version onwards we can take only try with resource without `catch` or `finally`.
	**Syntax**:
	```java
	try (e) {
	
	}
	```
The main advantage of try with resources is- we are not required to write `finally` block explicitly because we are not required to close resources explicitly hence untill 1.6 version `finally` block is just like hero but from 1.7-version onwards it is dummy and becomes zero.
